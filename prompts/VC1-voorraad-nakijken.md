## Waarom deze prompt
Op maandag kijkt kantoor na wat de KV's telden: tekorten, te veel, kapot. Per afwijking beslist kantoor wat er gebeurt (bestellen, uit de pool aanvullen, terug naar de pool, afschrijven, herstellen, aanvaarden). Die beslissingen vormen de aanvullijst voor wie in de Rozenweg aanvult; die persoon heeft geen desktop bij, dus de lijst bestaat als print (nu) en als gsm-scherm in de mobiele app (later, op dezelfde data).

## Punt 1 — Data en API
- Migratie: `nakijk_regels.kantoor_actie TEXT DEFAULT ''` (`bestellen|uit_pool|aanvaarden|naar_pool|laten_staan|afschrijven_bestellen|herstellen`), `nakijk_regels.kantoor_aantal REAL DEFAULT 0`, `nakijk_regels.kantoor_notitie TEXT DEFAULT ''`, `nakijk_regels.aangevuld INTEGER DEFAULT 0` (1 = afgevinkt in de Rozenweg), `nakijk_regels.aangevuld_door TEXT DEFAULT ''`, `nakijk_regels.aangevuld_op TEXT DEFAULT ''`, `nakijk_sessies.kantoor_afgerond_op TEXT DEFAULT ''`, `nakijk_sessies.kantoor_door TEXT DEFAULT ''`.
- `GET /api/nakijken?week=YYYY-MM-DD` (alleenKantoor): `tellers {te_keuren, niet_geteld, met_tekort, met_kapot, nagekeken}` en `bakken[]` = ALLE verwachte bakken en attributen van de kampmomenten van die week (werklijst 73: ook zonder sessie), per bak `{sessie_id|null, kampmoment_id, locatie, week, kv_naam, bak {code, naam, soort}, geteld, totaal, uitslag_tekst ("✓ alles klopt" / "tekort 1 · te veel 1 · kapot 1" / "niet geteld"), status (te_keuren|niet_geteld|nagekeken), ingediend_op, nagekeken_op}`.
- `GET /api/nakijken/sessie/:id` (of `?kampmoment_id=&bak=` voor een bak zonder sessie): kop + `items[{regel_id, naam, verwacht, aangetroffen, te_veel, kapot_aantal, notitie, foto_url, afwijking (klopt|tekort|te_veel|kapot|niet_geteld), kantoor_actie, kantoor_aantal, kantoor_notitie, aangevuld}]`, `vorige_tellingen[]` (dezelfde bak in vorige kampmomenten: datum, uitslag), `historiek[]` (wijzigingen + activiteiten_log + rit-checks laden/lossen van deze bak), `contact {kv_naam, kv_telefoon}`.
- `PUT /api/nakijken/regel/:id` (alleenKantoor): `{kantoor_actie, kantoor_aantal, kantoor_notitie}`; `POST /api/nakijken/sessie/:id/afronden` (zet `kantoor_status='nagekeken'`, `kantoor_afgerond_op`, `kantoor_door`; maakt uit de acties bestellen/afschrijven_bestellen de bestelregels aan via de bestaande tekorten/bestel-logica: zoek wat er is in `routes/voorraad.js`; bestaat er niets, dan GEVONDEN en enkel loggen); `POST /api/nakijken/herinnering` `{kampmoment_id}` → `activiteiten_log` + aanvraag-soort `herinnering_kv` zichtbaar in de kv-data (geen push).
- `GET /api/aanvullijst?datum=YYYY-MM-DD` (ingelogd personeel, elke rol): de handelingen uit alle afgeronde keuringen die nog niet `aangevuld` zijn, gegroepeerd per bak met `rek`/plaats (bak-locatie uit de bestaande bakken-tabel: rek/plank als die velden bestaan, anders de thuislocatie) en per handeling `{regel_id, stuk, aantal, soort (uit_pool|naar_pool|afschrijven|bestelling|nakijken), waar_tekst, aangevuld}`; `POST /api/aanvullijst/:regelId/aangevuld {aangevuld:true|false, foto_data?}` (log op naam). Dit is het contract voor de gsm-versie later.
